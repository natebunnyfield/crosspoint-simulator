# Albo round 432 -- the italic c's counter smoothed (2026-09-28)

Owner, on build 258: *"italic c got very fucked up"*.

**What was wrong** (verified at 900 px; no gate flagged it):
- Round 429's C_LOW thinned the lower left by reading the o's nib off each centerline sample's direction.
- A running maximum held the bottom, and each sample was shifted outward by half its loss.
- The counter came out with a point at its bottom in the Italic.
- In the Bold Italic it came out with a lump and a slit where the bottom joins.
- `albo_bumps`, `cmp_contour_hairs` and the glitch sweep all passed it.

**Fix** (`aldine.py`, `ALBO_ALD_C_LOW_SM` = 20; 0 = rounds 429-431):
- The THINNING (new width − old width) is smoothed with a raised-cosine window of 20 samples each side.
- The thinning is 0 outside the blend, so the top end that `fin_floor` reads and both finial stems are untouched.
- Bounds are identical: ink bottom −8, both cuts.
- Advance is +2 (Italic) and +1 (Bold Italic).

**Gates:**
- poor_gates: no delta (touch 0, hairs 0, glitch 0, contour census 1056).
- gates.sh UNCHANGED; approved 2/2.
- Roman and Bold byte-identical.
- Moved: c, cent, the ccedilla family, uniE004.

**Also in this commit, default OFF** (the italic-size option A, awaiting his ruling; `docs/albo-italic-size-baseline-2026-09-28.md`):
- Dials `ALBO_ALD_ROUND_OVER_BOT[_700]` and `ALBO_ALD_E_FLOOR_OVER[_700]` give the italic o c e the roman's bottom overshoot.
- The measured arm (1.25 / 0.055; 700: 1.0 / 0.018) gives Italic −16 −15 −15 and Bold Italic −15 −15 −15.
- At default the build is byte-identical.
