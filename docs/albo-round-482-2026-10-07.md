## Adversarial review before the build (2026-10-07)

A read-only reviewer covered this build's three changes: S-043's version floor
(`ios/testflight.sh`), S-036's streamed PUT (`src/WebServer.cpp`) and this
round's dials. It found nothing that would ship a visible bug or corrupt data.

**What it found, both fixed before the deploy:**
- A two-part version (`0.2`) passed the floor, then the floor's own X.Y.Z
  filter dropped its tag, so the next run would have gone back to 0.1.1.
  Versions must now be X.Y.Z.
- The "no marketing version" error could never print, because `grep` failed
  under `set -e` first. Now guarded.

Both were probed in a scratch repo: missing file, `0.2`, `0.1.0` refused;
unset and `0.1.2` accepted.

**Checked and CLEAN:**
- `received` cannot pass `bodyLength`.
- The firmware's `WebDAVHandler::raw` writes `raw.buf` synchronously and keeps
  no pointer to it, so reusing the recv buffer is safe.
- Bytes read along with the headers are emitted before `body` is freed.
- Nothing reads `body` after the loop for a raw request.
- The non-raw path is byte-identical to before.
- No route today is both raw and non-raw (`canRaw` is PUT only, and the
  firmware registers no PUT routes).
- `/usr/bin/sort -V` on this Mac orders 0.1.9 < 0.1.10 < 0.2.0.
- Pushing the version tag cannot fail a successful deploy.
- `exec` makes `$!` the simulator itself.
- The 0.72 thin hook reaches only A, M, V and W.
- Every dial is guarded above stem 84, so R and I cannot move.
